# Fixture B — the published-benchmark question, and what was done about it

Fixture A (`docs/FIXTURE-NOTTINGHAM.md`) demonstrates the commercial claim on
real geography. Fixture B was supposed to do something different and harder:
**test the solver against an optimum that someone other than us settled**, so
the engine is measured against the literature rather than against itself.

The obvious way to do that is to vendor a published instance — Solomon's VRPTW
set, or a TSPLIB case — and compare. **We do not, and this document is the
reason.** What we do instead is in §3.

---

## 1. The licence position

### 1.1 TSPLIB — disqualifying, and it says so plainly

TSPLIB is the standard TSP instance library, assembled by Gerd Reinelt. Its
licence terms and conditions permit use, copying and modification **for
non-commercial purposes** without fee, provided the copyright notice appears in
all copies, and state that **redistribution in whole or in part is forbidden
without prior written permission**.

Both halves rule it out here:

* This repository is AGPL-3.0-or-later **with a commercial dual licence**
  (`LICENSE-COMMERCIAL.md`). "Non-commercial use only" is not compatible with
  a licence we sell.
* Vendoring instance files into the repository *is* redistribution, in whole or
  in part, and we have no written permission.

This is not a grey area and it is not a risk worth taking to make a test look
more impressive.

### 1.2 Solomon's VRPTW instances — no licence at all

Solomon's 56 VRPTW instances (Solomon, 1987) are the standard time-window
benchmark. The best-known-solution tables are maintained by SINTEF, and the
instances are mirrored on dozens of sites, in several open-source projects and
on data-sharing platforms.

**None of that is a licence.** We could find no terms-of-use, copyright grant or
redistribution statement attached to the instances anywhere — they are
redistributed by academic custom, which is a social fact and not a legal one.
Widespread copying is evidence that nobody has objected; it is not permission.

Putting unlicensed third-party data into a repository that is sold commercially
is taking an unquantified risk on someone else's behalf. If it is worth taking,
it is worth taking deliberately, in writing, after asking Marius Solomon — not
by quietly adding a file.

### 1.3 OR-Library — an educational grant, not a commercial one

J. E. Beasley's OR-Library is the third obvious source. Its stated position is
that the data sets are made available for use by **students and teachers**
interested in OR, provided Beasley is acknowledged as their author. That is a
narrower grant than this repository needs, for the same reason as §1.1.

### 1.4 What would change this

Any one of these would let Fixture B use real published instances directly:

1. Written permission from the TSPLIB maintainers for redistribution in a
   commercial context.
2. A statement from Solomon, or from SINTEF as the maintainer of the
   best-known set, placing the instances under a named open licence.
3. Adopting an instance set that already carries one — if a benchmark family is
   published under CC0, CC-BY or similar, it can be vendored on the spot.

Until one of those exists, §3 stands.

### 1.5 Numbers are not datasets

One thing we **do** record: the published optimum or best-known tour length for
a named instance, in `tools/benchmark/best-known.json`, with its source.

A tour length is a fact stated in a paper. The coordinate table that produces it
is the dataset. Citing "berlin52's optimum is 7542, TSPLIB, Reinelt 1991" is
what every paper in the field does and is not redistribution of the instance.
So the harness can compare against the literature the moment the user supplies
the instance file themselves, without this repository ever holding one.

## 2. What Fixture B had to become

Two parts, because the original goal splits cleanly in two once the data cannot
ship.

## 3. Part one — an optimum that is a theorem

`tests/fixtures/convex-9.txt`, generated by `tools/fixture/convex.mjs`.

Nine nodes equally spaced on a circle of radius 10 km, travel at a fixed
30 km/h, node 0 as the depot. The external standard is this:

> For points in convex position, the optimal travelling-salesman tour is the
> convex-hull order.

The argument is elementary and old. Any tour with two crossing edges can be
shortened by uncrossing them — that is the triangle inequality — so an optimal
tour has no crossings, and the only non-crossing cyclic order of points in
convex position is the hull order. On a regular polygon the hull order is the
perimeter, whose length is

```
n · 2R · sin(π/n)  =  9 · 2 · 10 · sin(π/9) km  =  61.564 km  =  123.127 min
```

and 123.3 min once each leg is rounded to one decimal place, which is what the
matrix actually holds.

**This is a better test than a downloaded instance in three ways.** It is
redistributable, because we generated it. It is checkable by the reader without
trusting us, because the closed form is one line of trigonometry. And the
optimum is *exact* rather than *best-known*, so a failure is unambiguous rather
than a matter of being behind the state of the art.

### 3.1 Why nine nodes

Nine nodes leaves eight interior stops, which is exactly
`resequence::EXACT_LIMIT`. The fixture therefore sits on the documented boundary
of exhaustive search and proves the exact path returns the optimum at the
largest size it claims to. One node more and the honest answer becomes
`searched: false`.

### 3.2 Rounding is checked, not assumed

Rounding to one decimal place could in principle break the theorem: a rounded
matrix is not exactly Euclidean, so "an optimal tour has no crossings" no longer
follows for free.

`crates/lattice117-solve/tests/referee.rs` therefore checks the claim against
*this matrix* rather than asserting it from the geometry. All 40,320 interior
orderings are scored directly — not through the solver, so it is an independent
check and not the search grading its own work. Result:

| | |
|---|---|
| Optimal cost | 8 080 587 in Q16.16 = **123.3 min** |
| Optimal orderings | exactly **2** — the perimeter and its reverse |
| Second best | **+24.0 min** |

Two rather than one because a symmetric matrix cannot tell a tour from its
reverse; they cost the same to the last bit. The tie-break returns whichever is
lexicographically smaller *by position in the supplied round*, so which
direction comes back depends on the order the stops were listed in. The test
accepts either and says why — pinning one would pin an artefact of the input.

A 24-minute margin is not a rounding-width margin, so the theorem survives the
rounding comfortably on this instance.

### 3.3 The result that matters commercially

Both Tier 5 paths were run on it. They do not come out the same.

| Path | Result | Gap to the proven optimum |
|---|---|---|
| `resequence` (exhaustive, per round) | 123.3 min, hull order | **0.00%** — exact |
| `global` (Kondo, unassigned instance) | 226.8 min | **+83.9%** |

`resequence` finds the optimum from the worst starting order the instance has.
That is the path Tier 5 is sold on, and it is exactly optimal at its documented
limit.

`global` returns `0 → 8 → 1 → 6 → 7 → 4 → 3 → 5 → 2 → 0`, which crosses the
circle repeatedly against a perimeter that crosses it never. **83.9% above
optimum on a nine-node circle** — about the easiest non-trivial instance there
is. The cause is structural rather than a tuning miss: `K_CLUSTERS` is 5, so
nine nodes land in clusters of about two, and on points in convex position the
clustering carries almost no signal for the inter-cluster QUBO to work with.

**What this licenses, and what it does not.** `global` reports `exact: false`,
and a number like this is why that flag is not decoration. On this evidence the
global path must not be marketed as an optimiser. It is the fallback for an
instance with no vehicle assignment, it is honest about being a heuristic, and
it needs work before it is a selling point. The figure is pinned in the test
suite so it cannot drift in either direction unnoticed — including quietly
improving, which is worth knowing too.

## 4. Part two — a harness for the real instances

`tools/benchmark/` runs the solver against instance files **the user supplies**.
It ships no data. See `tools/benchmark/README.md`.

```
node tools/benchmark/run.mjs --tsplib  /path/to/berlin52.tsp
node tools/benchmark/run.mjs --solomon /path/to/C101.txt
```

Two details worth stating, because both are places a benchmark can flatter
itself without anyone noticing:

* **TSPLIB `EUC_2D` rounding is part of the instance.** The edge weight is
  defined as `nint(sqrt(dx² + dy²))`, nearest integer, and every published
  optimum is a sum of those integers. A reader that kept full precision would
  compute a different, incomparable — and smaller — number. The parser
  reproduces the rounding exactly, and the runner treats a *negative* gap as a
  bug to be investigated rather than a record to be announced.
* **Solomon's best-known figures are not comparable to a single tour.** They are
  the distance of a multi-vehicle, capacity-feasible solution that minimises
  vehicle count first. This engine models neither capacity nor fleet size, so
  the runner refuses to print a ratio for a Solomon instance and explains why
  instead. A number that looks like a score and is not one is worse than no
  number.

## 5. Summary

| | |
|---|---|
| Vendored third-party instance data | **none**, and §1 is why |
| External standard | a theorem, checkable in one line of trigonometry |
| `resequence` against it | exact, 0.00% gap, at `EXACT_LIMIT` |
| `global` against it | +83.9%, pinned, and not to be marketed as an optimiser |
| Real published instances | supported by `tools/benchmark/`, user supplies the file |
| Published optima | cited as facts in `best-known.json`, no data attached |
